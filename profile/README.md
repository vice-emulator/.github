# VICE - One Disk from Hardware You Had

## Bin number

One image from a disk or tape you own.
The model that matches it, written down.
A build of VICE you can replace, still zipped.
No cartridge file from a forum.
A keyboard you can use as the joystick if you do not have the mapping yet.

## First count

Select that model.
Load the image the way this build attaches a disk.
Wait for the first screen that machine would actually show.
Reset once. The same screen should return.

## Short count

Black screen after a model change. Put the model back.
The wrong drive device. The disk is attached and still "empty" because you used the other number. Fix the number. Do not fetch a different image.
A fast-load option you do not understand. Turn it off before you decide the disk is bad.
A path with odd characters. Move the file to a short folder and try once.

## Extra count

A second disk before the first has booted.
A save state from someone else.
Two emulators writing the same image.

![VICE on the Commodore model that matches the owner's disk image](https://www.linuxadictos.com/wp-content/uploads/VICE-emulador-de-Commodore.png)

## Damaged

The image will not directory. It may be the wrong model or a bad dump you made. The next step is the kept build or a new dump from your media, not a download.
You overwrote the image while "saving" from a state. Restore the file from the copy you should have made. If you did not copy it, that experiment is done.
Sound is a squeal. Return to defaults.
The window closes at once. Start from the zip you kept, not from a half-written config.

## Recount

Model matches the note.
The first screen returns after a reset.
The image file is still the one you stored.
You can quit and open the same config.

## Locked cage

Images live outside the program folder.
The working zip is not overwritten.
No shared folder of disks.
The note has the model on the first line, because the wrong machine wastes the hour.

## Not this warehouse

This does not supply Commodore software.
A "full set" is not a configuration step.
Firmware and ROMs you did not dump stay out.
A frontend full of names is not files you may add.
Speed left on is not how you judge a game. Turn it off.

## Next cycle

Kept zip, same image, same model.
A new build only in a second folder.
The first screen must return.
If it does not, delete the new folder.
Play after that, not instead of it.

## Variance

Wrong model, honest failure. Change the model back.
Right model, still empty. The attach slot is wrong.
New build, black screen. Use the old zip.
No image of your own. There is nothing to count.
